  🎯 SOLUTION FINALE - Uploads R2 Corrigés
═══════════════════════════════════════════════════════════════════

PROBLÈME RÉSOLU
---------------
❌ Les nouveaux documents uploadés n'allaient PAS vers R2
❌ Ils restaient en local malgré la configuration R2 correcte
❌ storage_setting = 'r2' dans la DB mais uploads toujours en local

CAUSE TROUVÉE
-------------
Le disk 'r2' dans config/filesystems.php lisait les credentials 
depuis .env (variables d'environnement) mais Dossy Pro stocke 
les paramètres R2 dans la BASE DE DONNÉES (table 'settings').

Résultat: Le disk R2 n'avait AUCUN credential lors des uploads!


═══════════════════════════════════════════════════════════════════
  ✅ CORRECTION APPLIQUÉE
═══════════════════════════════════════════════════════════════════

La méthode getStorageDisk() dans LegalLibraryController configure 
maintenant DYNAMIQUEMENT le disk R2 avec les credentials de la DB 
AVANT chaque upload.

C'est exactement ce que faisait déjà Utility::get_file() pour les 
téléchargements (c'est pourquoi les fichiers existants s'affichaient).

  🎯 CE QUI A ÉTÉ MODIFIÉ

Fichier modifié:
- app/Http/Controllers/LegalLibraryController.php
  → Méthode getStorageDisk() configure maintenant le disk R2 dynamiquement

Code ajouté (dans getStorageDisk):
config([
    'filesystems.disks.r2.key' => $settings['r2_key'],
    'filesystems.disks.r2.secret' => $settings['r2_secret'],
    'filesystems.disks.r2.region' => $settings['r2_region'] ?? 'auto',
    'filesystems.disks.r2.bucket' => $settings['r2_bucket'],
    'filesystems.disks.r2.endpoint' => $settings['r2_endpoint'],
    'filesystems.disks.r2.url' => $settings['r2_url'],
]);

Cette configuration se fait AVANT chaque upload, garantissant que
le disk R2 a toujours les credentials corrects depuis la DB.
